# 自用双端分发清单（不上架）

> 适用：融合 App（Flutter 3.24.0 / Java 17），个人与朋友自用。
> 目标：Android 拿到能直发的 APK；iOS 自测拿未签名 IPA 自行重签，给朋友装再按账号情况选 Ad Hoc / PWA。
> 原则：**能力不够就诚实降级，绝不假装成功**——沿用原工程的设计口径。

---

## 0. 开工前必须确认的三件事

- [ ] **源码包在手**：`uyghur-chinese-translator-source.zip` 未上传到资料库（已二次核验：资料库那个 zip 只有 10 个 H5/Python 文件、零 Dart 文件），需从本地 Git 仓库（分支 `main`，提交 `d57d149`）或原上传端取回
- [ ] **源码暂时找不到**：可直接用本包 `base-project/` 先跑第 1 节，把工具链验证掉，不等源码
- [ ] **知道 iOS 的成本下限**：非越狱 iPhone 只能装 Apple 签名过的 IPA；**自己测试不需要账号** —— `mode=unsigned` 出未签名 `.ipa` / `.app`，用自己的签名重签即可装机；只有给朋友分发才需要付费账号 + UDID（§3.2）或 PWA
- [ ] **明确不上架**：不走 Play Console / App Store Connect，不建应用记录，不传 AAB，不做内容分级

## 1. 第一次：让 CI 证明代码能编译（一次性，零密钥）

- [ ] 把补充包里的 `scripts/`、`.github/workflows/` 拷进工程根目录（原源码包缺 `verify_project.py` 与 `bootstrap.sh`，不拷会直接报「文件不存在」）
- [ ] 在 GitHub 建**完全空**的仓库（不勾 README / .gitignore / license）
- [ ] 准备勾选 `repo` 的 Personal Access Token（只在推代码时用一次，不写进仓库）
- [ ] 在工程根目录执行：

  ```bash
  export GITHUB_TOKEN=<PAT>          # 用完立刻在 GitHub 撤销
  export GITHUB_REPO=用户名/仓库名
  bash scripts/push_to_github.sh     # Token 不落盘、不写进 .git/config
  ```

- [ ] 首次 push 后看 `verify-first-build.yml`：`verify_project.py --scope all` → `flutter pub get` → `flutter analyze` → `flutter test` → `bootstrap.sh`（补原生壳 / 录音权限 / iOS 用途说明）→ `flutter build apk --debug`
- [ ] **这是原工程唯一没验证过的环节**。有任何一步红了，按 `docs/首次编译修复手册.md` 从上往下逐条修，别急着配签名
- [ ] 从 Artifacts 下载 `pubspec.lock` 回填仓库，锁定插件版本，避免后续构建因插件升级漂移
- [ ] 把 `bootstrap.sh` 生成的 `android/` / `ios/` 提交进仓库，别让每台机器各生成一份

> 别在 NAS 上跑这套：那台机器 8 GB 内存、常驻约 5 GB，扛不住 Gradle。交给 GitHub Actions。

## 2. Android：今天就能给朋友用

### 2.1 先出 debug 包（不需要任何密钥）

- [ ] 手动运行 `ci.yml` 或 `selfuse-android-apk`（`build_type=debug`）
- [ ] 下载 `app-debug.apk`，自己手机先装一遍，确认麦克风权限、RTL 维文排版、翻译主链路都正常

### 2.2 再出 release 包（可选，但推荐）

- [ ] 本机执行 `bash scripts/make_keystore.sh`，生成 `android/app/selfuse.jks`
- [ ] 把 `android/key.properties.example` 复制为 `android/key.properties` 并填写；确认 `.gitignore` 已排除 `*.jks` / `key.properties` / `dist/`
- [ ] 按 `android/signing-snippet.gradle` 的注释合并 `android/app/build.gradle`（**不要整文件覆盖**）
- [ ] GitHub Secrets 配置 4 项：`ANDROID_KEYSTORE_B64`、`ANDROID_KEYSTORE_PASS`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASS`
- [ ] 手动运行 `selfuse-android-apk`，`build_type=release` → 产物 `app-arm64-v8a-release.apk` 等
- [ ] 发给朋友：微信/网盘传文件 → 手机开启「允许安装未知来源应用」→ 安装

### 2.3 Android 侧验收

- [ ] 同一个包名、同一个签名，后续版本能**覆盖升级**（别每次换 keystore）
- [ ] `adb install -r` 覆盖安装一次，确认不报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`
- [ ] 首次启动弹麦克风授权，拒绝后有可读提示而不是崩溃

---

## 3. iOS：按你的账号情况三选一

### 3.1 自己测试 → 未签名 IPA（零账号、零 Secrets，推荐先走这条）

- [ ] 手动运行 `selfuse-ios-ipa`，`mode=unsigned`（默认）
- [ ] 产物 `Runner-unsigned.ipa` + `Runner-unsigned.app.tar.gz`，**两者都未签名**
- [ ] 用自己的签名方式（免费个人签名 / 付费证书 / 企业证书）重签后装到自己 iPhone 测试；**免费个人签名 7 天后过期需重签**
- [ ] 明确知道：**未签名包不能直装，也给不了朋友**；给朋友装看 §3.2 / §3.3
- [ ] 如果希望朋友也能零成本用 → 走 PWA（Safari 添加到主屏幕），不要在 IPA 上耗时间

### 3.2 有账号 → Ad Hoc IPA（推荐给固定几个朋友）

- [ ] Apple Developer 账号（约 ¥688/年），在 Certificates, Identifiers & Profiles 里建 App ID（Bundle ID 与工程一致）
- [ ] 收集朋友设备 UDID：iPhone 设置 → 通用 → 关于本机，或用 Xcode Devices 窗口 / Apple Configurator 读取；**上限 100 台**
- [ ] 把 UDID 登记进 Devices，创建 **Ad Hoc** Provisioning Profile（包含这些设备）
- [ ] 导出 Distribution 证书 `.p12` + 该 `.mobileprovision`
- [ ] 替换 `ios/ExportOptions-AdHoc.plist` 里 3 个占位：`REPLACE_WITH_TEAM_ID`、`REPLACE_WITH_BUNDLE_ID`、`REPLACE_WITH_ADHOC_PROFILE_NAME`
- [ ] GitHub Secrets 配置：`IOS_P12_BASE64`、`IOS_P12_PASSWORD`、`IOS_PROVISION_B64`、`IOS_KEYCHAIN_PASSWORD`
- [ ] 手动运行 `selfuse-ios-ipa`，`mode=adhoc` → 产物 `.ipa`
- [ ] 分发：Apple Configurator / Xcode Devices / 自建 HTTPS 页面 + `itms-services` 清单，或直接 TestFlight

### 3.3 有账号 → TestFlight 内部测试（最省事）

- [ ] 内部测试组**免审核**，最多 100 名内部成员，用邮箱邀请即可
- [ ] 这条路不需要收集 UDID，但仍需 App Store Connect 建 App 记录 + App Store  Distribution 证书
- [ ] 本包的工作流刻意不接 TestFlight（避免和「不上架」定位混淆）；要走这条，把 `ExportOptions-AdHoc.plist` 换成 `method=app-store` 并在 fastlane 里加 `upload_to_testflight`

### 3.4 iOS 侧验收

- [ ] `ios/Runner/Info.plist` 有 `NSMicrophoneUsageDescription`，中维双语写清「用于语音翻译，录音仅实时处理」
- [ ] Xcode 里 Team / Bundle ID / Signing 已补齐（`bootstrap.sh` 生成的壳不含这些）
- [ ] 真机安装后按住说话能弹出麦克风授权，维文 RTL 不倒序
- [ ] Ad Hoc 包在**未登记 UDID** 的设备上应装不上——这是预期行为，不是 bug

## 4. 自用也不能省的部分

| 项 | Android | iOS |
|---|---|---|
| 录音权限声明 | `RECORD_AUDIO` + 用途说明 | `NSMicrophoneUsageDescription` |
| 网络权限 | `INTERNET` | ATS 允许访问讯飞 / Azure 域名 |
| 密钥不硬编码 | 讯飞 AppID/Key 走环境变量或 CI Secrets | 同左 |
| 录音告知 | 面对面使用前口头说明「我录一下翻译」 | 同左 |
| 翻译结果提示 | 仅供沟通参考，正式文书人工校对 | 同左 |
| 授权边界 | Hunyuan-MT 社区许可证的地域排除条款；自用范围一般不受影响，但别对外提供服务 | 同左 |

> `--dart-define` 不等于加密，密钥会编进二进制、可逆向提取。自用内测没问题；若以后要上架，改成后端签发已签名 wss URL（替换 `XfyunSocketConnector`，协议层不动）。

**可以省掉的**：商店截图/描述/关键词、隐私政策公开 URL、内容分级问卷、数据安全表单、IAP 接入、审核 Guideline 自查、账号注销入口（若无账号系统）。

## 5. 常见坑对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 首次 push 的 CI 挂掉 | 从没真编译过，静态校验覆盖不到 Gradle / CocoaPods | 看 Actions 日志逐条修，先过 `flutter analyze` / `flutter test` |
| `bootstrap.sh` 后 iOS 编译不过 | 生成的壳没有 Signing 配置 | Xcode 打开 `Runner.xcworkspace` 补 Team 与 Bundle ID |
| Ad Hoc IPA 装不上 | 设备 UDID 没登记进该 profile | 重新生成包含该设备的 profile |
| 覆盖安装报签名不一致 | 换了 keystore 或之前装的是 debug 签名包 | 卸载重装一次，之后固定同一 keystore |
| 讯飞 TTS 报 `11200` | 维语发音人未在控制台开通 | 控制台单独开通，`vcn` 值只能从控制台查 |
| 维语字幕重复 | 讯飞 ASR 会话累加中间结果 | 注入 `XFYUN_IAT_APPEND=0` |
| 长时间使用字符消耗大 | 预译把消耗放大约 3–5 倍 | 调大 `draftThrottle` |
| 朋友在 iPhone 上装不了 | 未签名 .app 受系统限制 | 走 3.2 / 3.3，或改用 PWA |

## 6. 明确的能力边界

- 本环境无 Flutter SDK / Android SDK / Xcode，**所有构建与真机安装都在你本地或 CI 完成**，本清单只负责把路径和坑写清楚。
- 本包自带的 `verify_project.py` / `bootstrap.sh` / `push_to_github.sh` / `verify-first-build.yml` 已做过语法校验与模拟工程补丁验证，但**未经真实 Flutter 编译**；第一次绿灯以 GitHub Actions 日志为准。
- 证书、keystore、p12、密码一律不代收、不落盘、不写入任何文件；只按 `docs/密钥与证书管理.md` 的方法由你生成。
- 「同传」是分句级准实时（静音判句 2–3 秒 + 一次 API 往返），不是毫秒级流式；瓶颈始终是维语 ASR/TTS，不是翻译。
