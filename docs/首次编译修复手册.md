# 首次编译修复手册（从没真编译过的 Flutter 工程）

> 适用：融合 App（Flutter 3.24.0 / Java 17），个人与朋友自用、不上架。
> 目标：让 `verify-first-build.yml` 变绿。这是原工程唯一没验证过的环节，
> **先过这关，再碰签名与分发**。

---

## 0. 排查顺序（别跳步）

```
静态自检 → pub get → analyze → test → bootstrap（补原生壳）→ build apk --debug
```

每一关的输出都是下一关的前提。CI 日志从上往下看，**只修第一条报错**，
后面的大概率是连锁失败；修完重跑，别一次性改一堆。

---

## 1. 版本对齐基线

| 组件 | 固定值 | 不对齐时的典型症状 |
|---|---|---|
| Flutter | `3.24.0` stable | 插件要求更高 SDK，`pub get` 版本解析失败 |
| Dart | `>=3.3.0 <4.0.0`（3.24 自带 3.5.x） | `environment.sdk` 约束冲突 |
| JDK | `17`（Temurin） | Gradle `Unsupported class file major version` |
| Android Gradle Plugin | 由 Flutter 模板决定，**不要手改** | `Minimum supported Gradle version` |
| Kotlin | 由模板 `settings.gradle` 决定 | `Kotlin version mismatch` |
| minSdk | Flutter 3.24 模板默认 `21` | 插件报 `minSdkVersion 23 required` |
| iOS deployment target | `12.0`+（`bootstrap.sh` 显式写） | CocoaPods 报 `requires iOS 13` |
| CocoaPods | macOS runner 自带，需 `pod repo update` 兜底 | `CDN: trunk Repo update failed` |

查看实际版本：`flutter --version`、`java -version`、`flutter doctor -v`。

## 2. 症状速查表

### 2.1 `pub get` 阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| `Invalid package name` / `pubspec.yaml` 解析失败 | `name` 含中文、大写或连字符（脚手架默认会写成中文，已在本包地基里修正为 `uyghur_interpreter`） | 改成 `^[a-z][a-z0-9_]*$`，同步改所有 `import 'package:<name>/...'` |
| `version solving failed` | 某个插件锁死旧版，与 Dart 3.5 不兼容 | `flutter pub outdated` 看依赖树；逐个升到支持 Dart 3 的版本，别用 `--no-version-check` 硬绕 |
| `SDK version` 约束冲突 | `environment.sdk` 与 Flutter 3.24 自带的 Dart 不匹配 | 对齐到 `>=3.3.0 <4.0.0`，或换对应 Flutter 版本 |
| 国内网络超时 | pub.dev / pub get 拉不到 | CI 上设 `PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`；**别把镜像写进仓库**，放 workflow 的 env |
| `pubspec.lock` 每次 CI 都变 | 没提交 lock 或用了 `^` 宽松约束 | 首次 CI 会从 Artifacts 产 `pubspec.lock`，回填并提交 |

### 2.2 `flutter analyze` 阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| 几十条 lint 一涌而出 | 原工程 `analysis_options.yaml` 规则与新版 `flutter_lints` 不同 | 先看是不是 `info` 级：`flutter analyze --no-fatal-infos --no-fatal-warnings` 确认能过，再分批清理；**别一上来全 `ignore`** |
| 生成文件被 lint 扫 | `*.g.dart` / `*.freezed.dart` 未排除 | `analysis_options.yaml` 的 `analyzer.exclude` 加 `**/*.g.dart`、`build/**` |
| `deprecated_member_use` | 3.24 废弃了一批 API（如 `MaterialStateProperty`→`WidgetStateProperty`） | 按提示逐个替换，改动不大但必须真改 |
| `undefined_*` 大批出现 | 缺 `pub get` 产物或某个包没引 | 确认 `flutter pub get` 在 analyze 之前跑过 |

### 2.3 `flutter test` 阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| `No tests found` / 退出码非 0 | 没有 `test/` 或测试文件命名不以 `_test.dart` 结尾 | 补一个最小 `test/smoke_test.dart`（本包地基已带） |
| 网络 / 平台通道相关测试挂 | 单测里直接调了讯飞 / Azure 的真实 API | 用 `TestDefaultBinaryMessengerBinding` 或 mock 掉 Platform Channel，别在 CI 里打真实云端 |
| golden 文件不一致 | 字体 / 渲染引擎版本差异 | 自用场景建议直接删 golden 断言，不值得维护 |
| 测试通过但 CI 仍红 | `flutter test` 退出码被管道吞掉 | 去掉 `| tee` 之类的管道，或加 `set -o pipefail` |

### 2.4 Android 构建阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| `android/` 目录不存在 | 工程只写了 Dart 层，没生成原生壳 | `bash scripts/bootstrap.sh`（会补 `RECORD_AUDIO` / `INTERNET` 权限） |
| `Unsupported class file major version 61` | JDK 不是 17 | `actions/setup-java@v4` + `distribution: temurin` + `java-version: '17'` |
| `Minimum supported Gradle version` | 手动改过 `gradle-wrapper.properties` | 回到 Flutter 3.24 模板默认值，别自定义 |
| 插件报 `minSdkVersion XX required` | 讯飞 / 音频插件要求高于 21 | 改 `android/app/build.gradle` 的 `minSdkVersion`（**不是** `flutter.minSdkVersion`），改完确认旧手机还能装 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 之前装的是 debug 签名包，现在换 release 签名 | 卸载重装一次，之后固定同一 keystore |
| 构建成功但按住说话没反应 | 主 manifest 缺 `RECORD_AUDIO`，或拒绝授权后没提示 | `bootstrap.sh` 补权限；首次启动显式请求授权并处理拒绝分支 |

### 2.5 iOS 构建阶段（仅 macOS runner）

| 症状 | 原因 | 处理 |
|---|---|---|
| `ios/` 缺 `Runner.xcworkspace` | 没生成原生壳 | `bootstrap.sh`；之后 `pod install --repo-update` |
| `CocoaPods could not find compatible versions` | 某插件要求 iOS 13+ | 把 `ios/Podfile` 的 `platform :ios` 提到插件要求的最低版本（改 `IOS_DEPLOY_TARGET` 环境变量重跑） |
| `No signing certificate` / `Team` 为空 | `bootstrap.sh` 刻意不配签名 | Xcode 打开 `ios/Runner.xcworkspace` 补 Team / Bundle ID；无 Apple 账号时选 `mode=unsigned`，接受「只能自己装」 |
| Ad Hoc IPA 朋友装不上 | 设备 UDID 没登记进 provisioning profile | 重新生成包含该设备的 profile，这是预期限制不是 bug |
| `NSMicrophoneUsageDescription` 缺失被拒 | Info.plist 没写用途说明 | `bootstrap.sh` 已补中维双语说明 |

### 2.6 配置与凭证

| 症状 | 原因 | 处理 |
|---|---|---|
| CI 里讯飞报鉴权失败 | AppID / Key 只在本机环境变量里 | GitHub Secrets + `--dart-define`；**注意这不等于加密**，密钥会编进二进制可逆向，自用内测可接受 |
| 静态自检提示疑似硬编码密钥 | 代码里写了明文 Key | 换成 `String.fromEnvironment` / `Platform.environment`；要卡死就给自检加 `--strict-secrets` |
| 每次出包版本号都一样 | `version` 没递增 | `pubspec.yaml` 的 `1.0.0+N` 里 `N` 每次 +1，Android 才能识别为升级 |

## 3. 门禁变绿之后的收尾

- [ ] 从 Artifacts 下载 `pubspec.lock` 回填仓库并提交，锁定插件版本
- [ ] 把 `bootstrap.sh` 生成的 `android/` / `ios/` 提交进仓库（别让每台机器各生成一份）
- [ ] 确认 `.gitignore` 排除了 `*.jks` / `key.properties` / `*.p12` / `*.mobileprovision` / `dist/`
- [ ] 自己手机装一遍 debug APK：麦克风授权、维文 RTL 不倒序、翻译主链路
- [ ] 这时才按 `docs/自用双端分发清单.md` 去配签名与分发

## 4. 诚实的能力边界

- 本环境**无 Flutter SDK / Android SDK / Xcode**，本手册与配套脚本均为文件级产物，
  **未真编译、未真打包、未代推仓库、未代签证书**。
- 上述报错表是「从未编译过的 Flutter 工程」的高频项，不是预言；实际以 CI 日志为准。
- 首次编译若一次性红十几个错，属正常——静态校验过 373 项，也覆盖不到 Gradle / CocoaPods。
  按第 0 节顺序逐条修即可。
- 不要在 8 GB 内存、常驻约 5 GB 的 NAS 上跑 Gradle，交给 GitHub Actions。
